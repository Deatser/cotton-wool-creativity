# cotton wool creativity — сайт ватных ёлочных игрушек

Магазин ватных ёлочных игрушек ручной работы. Перенесён с конструктора
sites.google.com и собран своим кодом: HTML, CSS, JavaScript, без готовых движков.

Страницы статические, поэтому грузятся быстро и хорошо индексируются. Каталогом
управляет хозяйка сайта через админку прямо на страницах, без правки файлов.

## Как запустить у себя

```
py -m pip install -r requirements.txt
py serve.py
```

Сайт откроется на http://127.0.0.1:8000

**Обычный `py -m http.server` не подойдёт.** Он отдаёт файлы, но не умеет
принимать правки из админки, и та будет ругаться, что сохранять некуда.

## Что где лежит

```
serve.py            сервер: отдаёт сайт, принимает правки и файлы из админки
build.py            сборщик: из data/toys.json и photos/ делает готовый сайт
data/toys.json      каталог: 59 игрушек, названия, размеры, цены, разделы, фото
templates/          шаблоны страниц (Jinja2)
static/css/         стили витрины, админки и страницы входа
static/js/          скрипты: витрина, вход, админка
static/fonts/       Comfortaa, лежит у нас, а не тянется со сторонних серверов
photos/             оригиналы фотографий, 332 МБ, только для сборки картинок
site/               ГОТОВЫЙ САЙТ, это и заливается на хостинг
secret/             секретный адрес страницы входа, вне репозитория
.env                настройки Firebase, вне репозитория
```

Папка `site/` пересобирается целиком, руками там ничего не правят.

## Про две папки с фотографиями

`photos/` — оригиналы как есть, по 3-6 МБ на кадр. На хостинг не едут и в
репозиторий не попадают.

`site/img/igrushki/` — то, что реально видит покупатель: обложка каталога
квадратом 600 и 300 px, фото на странице 900 px, при увеличении 1600 px.
Из 332 МБ оригиналов получается 69 МБ.

`site/img/upload/` — файлы, загруженные через админку. Единственная папка
внутри `site/`, которую сборщик не трогает.

## Админка

Вход по секретному адресу, он лежит в `secret/login-path.txt` или задаётся
переменной `LOGIN_PATH`. Ссылок на него нигде на сайте нет, страница закрыта
от поисковиков. Регистрации нет: единственный пользователь заводится вручную
в консоли Firebase, оттуда же и пароль.

Что умеет хозяйка сайта:

- добавлять игрушки: название, высота, цена, раздел, примечание;
- загружать обложку, фотографии и видео, менять их порядок перетаскиванием;
- переставлять карточки в каталоге мышкой или пальцем на телефоне;
- править и удалять игрушки.

После каждого сохранения сервер обновляет `data/toys.json` и пересобирает сайт,
поэтому у новой игрушки сразу появляется своя страница со своими заголовком,
описанием и микроразметкой.

Адрес страницы игрушки собирается из названия: «Дед мороз» превращается в
`/igrushki/ded-moroz/`. У существующей игрушки адрес не меняется при
переименовании, иначе ломались бы ссылки и выдача в поиске.

## Выкладка на хостинг

Хостинг Amvera, приложение на Python. Репозиторий хранит только код и стартовый
сайт, всё, что добавляет хозяйка, живёт на постоянном диске `/data` и переживает
любую пересборку.

Переменные в панели, все на этапе «Запуск»:

| Переменная | Значение |
|---|---|
| `STORAGE_DIR` | `/data` |
| `LOGIN_PATH` | адрес страницы входа |
| `FIREBASE_API_KEY` и ещё пять | из `.env` |

Секретом помечается только `LOGIN_PATH`. Значения Firebase не секретны: они всё
равно уходят в браузер, доступ ограничивают список разрешённых доменов и правила
безопасности.

При первом запуске приложение переносит стартовый сайт и каталог на диск, дальше
деплой кода их не трогает.

## Как поменять каталог руками

Обычно это делается через админку, но при желании можно править `data/toys.json`
и запускать `py build.py`. Поля карточки:

- `name`, `size`, `note` — подпись под фотографией в каталоге;
- `price` — число или `null`. При `null` цена и кнопка «Купить» не показываются;
- `section` — `in_stock`, `repeat` или `custom`;
- `slug` — адрес страницы, `/igrushki/<slug>/`;
- `folder` и `photos` — папка в `photos/` и имена файлов, для игрушек из переноса;
- `coverUrl` и `media` — готовые файлы внутри `site/`, для добавленных через админку.

Порядок игрушек в файле задаёт порядок в разделе.

## Перед публикацией

В `build.py` строка `BASE_URL` — подставить настоящий домен, от него считаются
`canonical` и `sitemap.xml`.
